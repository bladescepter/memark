# 工具定义压缩执行方案

状态：代码与自动测试已完成，真实模型调用与 `/reload` 验收待完成。范围：只精简 `memark_recall`、`memark_remember` 的模型可见文字，不改工具名、参数结构、校验和审核流程。

## 背景

工具定义随每个请求发送。按 2026-10-05 至 2026-11-05 的 magpie 用量记录和 Pi 会话估算（token 为估算值，未用分词器实测）：

| 常驻部分 | 字符数 | 估算 token |
|---|---:|---:|
| `memark_remember` 定义 | 2,200 | ~1,050 |
| 基线注入 | 366 | ~310 |
| `memark_recall` 定义 | 578 | ~290 |
| 系统提示 tools/rules 段中的 memark 行 | 462 | ~150 |
| 合计 | 3,606 | ~1,800 |

`memark_remember` 占常驻部分近六成，但全部会话只调用过 21 次。

历史上 6 次报错全部是 `zone=project` 时传错 type 或 category（如 Principle、Preference，或自定义 category）。现有描述很长，却没有写明项目区允许哪些 type。因此本次压缩的同时要补上这条规则。

## 目标

| 工具 | 现状（字符） | 目标（字符） | 目标（估算 token） |
|---|---:|---:|---:|
| `memark_remember` | 2,200 | ≤ 1,500 | ~650 |
| `memark_recall` | 578 | ≤ 450 | ~220 |

合计节省约 470 token，约占常驻部分的四分之一。字符目标是验收依据；若为保留必要规则而略超，在提交说明中写明原因。

## 改动

### 1. `curator.ts`：`memark_remember` 描述

替换为：

> 将用户明确要求记住的内容写入记忆仓库，写入前由用户审核预览。跨项目规则用 zone=personal；单项目内容用 zone=project 并提供 project（优先核对已有项目），type 只能是 Decision/Topic/Incident/Handoff。目录由 type 推导，通常不传 category。Handoff 必须设置 expires。修改已有记忆用 edit=<仓库相对路径>。新项目及辅助文件须在预览中获批。不适用的可选参数省略或传 null。报错时按提示修正，不得改变适用范围。

相比现状：

- 删除 `运行：${runtime.label}`。报错信息和 `/memory status` 仍带版本。
- 删除 pending 与离线细节。实施时确认 `savePending` 等返回文字已足够说明结果；不足则补到返回文字，不放回描述。
- 新增项目区 type 白名单。

### 2. `curator.ts`：参数说明

- `optionalNullable`：删除自动追加的“；不适用时省略或传 null”，改由工具描述说明一次。**保留 `Type.Union([schema, Type.Null()])`**，它是 v0.3.5 为兼容强制全字段必填的模型接口加入的。
- `layer`：`个人区可省略，按 type 推导；项目区不使用`（保持不变）。
- `category`：缩短为 `仅个人区 Context 可用`。
- `edit`：缩短为 `要原地改写的记忆路径；只更新 title/description/body/tags`。
- `as_pending`：缩短为 `只保存为本机待审核候选`。
- 其余参数说明保持不变。

### 3. `index.ts`：`memark_recall` 描述

替换为：

> 检索 Markdown 长期记忆库的本地快照，不等待网络。默认范围为个人区加当前项目；all_projects=true 时检索全部项目。过期记忆不会返回。最多返回 10 个文件，总输出不超过 50KB/2000 行。

### 4. 不改动

- `promptSnippet`、`promptGuidelines`：其中“仅在用户明确要求时写入”的规则保留。
- 基线注入：已有长度上限，不在本次范围内。
- 代码校验和报错文字：除非第 1 步确认需要补充返回文字。

## 验证

1. `npm test`：严格类型检查和全套回归通过。
2. 对比改动前后定义的字符数，确认达到目标。
3. 实测（需用户确认后写入）：
